# AI Business Intelligence Assistant

A small application that lets a business user ask questions about sales data in
natural language. The app turns the question into a SQL query, validates it, runs it on
a read-only SQLite database, and returns the answer together with the SQL used and the
supporting figures.

## 1. Features

- Loads the supplied sales CSV into an SQLite database (`load_data.py`).
- Answers questions with real database queries, not LLM arithmetic:
  total revenue, top product, top region, monthly revenue trend, and revenue change
  between two months. Other questions are handled if Gemini can express them as a SELECT.
- Uses Google Gemini to convert the question into SQL.
- Falls back to deterministic rule-based SQL for the five standard question types when
  Gemini is overloaded or rate limited, so the app keeps answering.
- REST API (`POST /ask`) with structured JSON responses and clear error codes.
- Simple web page to ask questions and view the answer, the SQL and the supporting data.
- Automated tests (11) that run without an API key or network access.

## 2. Technologies

Python 3.13, FastAPI, Uvicorn, SQLite, Pandas, Google Gen AI SDK (`google-genai`),

## 6. Example API Request

`POST /ask`

```json
{ "question": "What is the total revenue?" }
```

Response:

```json
{
  "question": "What is the total revenue?",
  "answer": "Result: total_revenue = 1,439,200",
  "sql": "SELECT SUM(Quantity * Unit_price - Discount_amount) AS total_revenue FROM sales WHERE ...",
  "source": "llm",
  "supporting_data": [{ "total_revenue": 1439200.0 }]
}
```

`source` is `llm` (Gemini generated the SQL), `cache` (a repeated question) or
`fallback` (rule-based SQL used because Gemini was unavailable).

Error codes: 400 (empty, too long, destructive or unsafe request), 422 (question cannot
be answered from the data), 503 (Gemini unavailable and no fallback applies), 500
(unexpected error).

## 7. Architecture

```
Browser (index.html)
   |  POST /ask {question}
   v
FastAPI (main.py)        -> maps errors to HTTP status codes
   v
ai_engine.ask_question()
   1. Input checks: empty / too long / destructive wording -> rejected
   2. Gemini converts the question into one SELECT (JSON: supported, sql, reason)
        - Gemini unavailable -> rule-based fallback SQL
   3. SQL validator: single SELECT only, no write keywords, no comments
   4. Execution on a read-only SQLite connection (mode=ro)
   5. Answer text is built from the result rows; SQL and rows are returned as evidence
```

## 8. Data Storage and Cleaning

- The CSV (51 transactions) is loaded into one SQLite table named `sales`.
- Dates are converted from `dd-mm-yyyy` to ISO `YYYY-MM-DD` during loading, because
  SQLite date functions such as `strftime` only understand ISO dates.
- Invalid records are kept in the database but excluded at query time with:
  `Status = 'Completed' AND Quantity > 0 AND Unit_price IS NOT NULL`.
  This removes TXN0033 (returned), TXN0034 (quantity 0) and TXN0051 (missing unit price),
  leaving 48 valid transactions. Keeping the raw rows means nothing is silently lost.
- Revenue = `Quantity * Unit_price - Discount_amount`. Total valid revenue is 1,439,200.

## 9. Preventing Unsafe or Incorrect Answers

- All figures come from SQL executed on the database, never from the model's own arithmetic.
- The model must return `supported: false` for questions the data cannot answer
  (for example unrelated topics), which the API reports as an error.
- Destructive requests ("delete", "drop", "update" ...) are rejected before any model call.
- Generated SQL must be a single SELECT with no write keywords and no comments.
- The database connection is opened read-only, so writes are impossible even if validation
  were bypassed.
- Every answer shows the SQL and the supporting rows so it can be checked.

## 10. Run Automated Tests

```powershell
python -m pytest -v
```

The 11 tests cover: valid questions (total revenue, top product, top region, April vs May),
an LLM-generated query with a mocked model reply, invalid input (empty question, destructive
request, unsupported question, malicious SQL returned by the model, multiple statements),
and an edge case (returned, zero-quantity and missing-price rows are excluded).
Gemini is mocked, so the tests are fast and need no API key.

## 11. Known Limitations

- The free Gemini tier returns 503 (overloaded) and 429 (quota) errors under load. The app
  retries across two models, then uses the rule-based fallback, which only understands the
  five standard question types.
- Month names are assumed to refer to 2026, the only year in the data.
- The destructive-word filter is keyword based and may reject a harmless question that
  contains a word such as "update".
- Single table, no authentication, no conversation memory, small dataset.
